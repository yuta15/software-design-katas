# Invoice Batch Observer

## テーマ

毎月の利用明細から、顧客ごとの請求書を一括発行するバッチ処理を作ります。

請求担当者は、対象となる請求月を指定してバッチを実行します。バッチは対象顧客を一人ずつ処理し、請求書を発行します。

実際のメール送信や外部通信は行いません。

## ユーザーストーリー

### 請求書を一括発行する

請求担当者として、月ごとの請求書を顧客ごとに手作業で発行したくありません。そのため、請求月を指定して、対象となるすべての請求書を一度に発行したいです。

### 発行状況を確認する

請求担当者として、時間のかかる処理がどこまで進んでいるか分からない状態を避けたいです。そのため、バッチの開始、顧客ごとの処理結果、処理全体の完了を確認したいです。

### 失敗した顧客を確認する

請求担当者として、一部の顧客で請求書の発行に失敗した場合、その顧客と失敗理由を確認したいです。また、一人の失敗によって、ほかの顧客の請求書発行まで中止してほしくありません。

### 実行結果を複数の用途で利用する

運用担当者として、同じ進捗や処理結果を、画面への表示や実行履歴の記録など複数の用途で利用したいです。用途の追加や取り外しによって、請求書の発行処理自体は変更したくありません。

## 業務ルール

- 請求書は、指定された請求月と顧客の組み合わせごとに発行する
- 請求月に確定済みの利用明細がある顧客だけを処理対象にする
- 未確定の利用明細は請求額に含めない
- 請求額は、対象となる利用明細の金額を合計して求める
- 利用明細の金額に負数は使用できない
- 対象となる利用明細がない顧客には請求書を発行しない
- 同じ顧客と請求月の請求書を重複して発行しない
- 一人の顧客で発行に失敗しても、残りの顧客の処理を継続する
- バッチ完了時に、発行件数、対象外件数、失敗件数を確認できるようにする
- 失敗時には、対象の顧客と失敗理由を確認できるようにする

## 実現したい処理

請求担当者がバッチを開始すると、処理の開始が通知されます。顧客の処理が終わるたびに、発行、対象外、失敗のいずれかの結果と現在の進捗が通知されます。

すべての顧客を処理した後は、発行件数、対象外件数、失敗件数を含む実行結果が通知されます。

通知を利用する処理は複数登録でき、必要に応じて追加または取り外せるものとします。
